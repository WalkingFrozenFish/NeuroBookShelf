# Как устроен NeuroBookShelf

Документ для человека, который впервые открывает репозиторий и будет менять код. Здесь зафиксировано то, что уже есть. Установка окружения — в [SETUP.md](SETUP.md), правила слоёв — в [ARCHITECTURE.md](ARCHITECTURE.md), список возможностей — в [README.md](README.md).

В окне приложение называется NeuroBookShelf. Крейт Rust — `local-library-reader`, идентификатор Tauri — `com.locallibrary.reader`. Это одно и то же приложение.

## Что делает программа

Человек импортирует PDF. Приложение копирует файл к себе и показывает его в библиотеке. В читалке страница рисуется локально. С выделенной области или со всей страницы можно снять текст, перевести его с английского на русский и оставить карточку поверх страницы. Рядом живут закладки, заметки и словарь.

Сети для чтения не нужно. Модели OCR и перевода лежат на диске и в Git не входят.

Читаются только PDF. Перевод только английский → русский. Словарь — ручные пары «фраза → перевод». Он не подставляется в модель и не меняет текст на странице.

## Экраны

Верхнее меню в `src/App.tsx`: Библиотека, Читалка, Корзина. Словарь открывается карточкой внутри библиотеки и не занимает отдельную кнопку.

**Библиотека** (`src/pages/LibraryPage.tsx`). Слева полки и теги, справа карточки книг. Поиск фильтрует названия. Книгу можно положить на полку перетаскиванием: полка — это связь в базе, файл при этом не двигается. У книги есть меню: переименовать, сменить полки и теги, экспортировать копию, убрать переводы, убрать заметки, отправить в корзину. Кнопка «Импорт PDF» копирует выбранный файл в каталог библиотеки.

В настройках библиотеки: путь к базе и его смена, тема (`light`, `dark`, `sage`, `rose`, `mist`), примеры, сброс полок, сброс тегов, очистка библиотеки. «Добавить примеры» записывает в эту же базу полки, теги, слова и короткие PDF, две книги кладёт в корзину. Повторное нажатие добавляет только то, чего ещё нет. Данные примеров живут в `src-tauri/src/seed.rs`.

**Словарь** (`src/pages/DictionaryPage.tsx`). Общий словарь: алфавит EN/RU, поиск, правка и удаление. Это тот же набор записей, который в читалке называется «общим».

**Читалка** (`src/pages/ReaderPage.tsx`). Слева миниатюры, по центру страница, справа панель. Масштаб и номер страницы запоминаются на документ. Выделение мышью задаёт область в долях страницы от 0 до 1, не в пикселях экрана.

Правая панель (`src/pages/ReaderSidePanel.tsx`):

- заметки ко всей книге или к странице;
- закладки;
- сохранённые переводы страницы: показать карточку, добавить фразу в словарь книги или в общий, удалить блок;
- словарь этой книги и общий словарь (`src/pages/ReaderDictionary.tsx`).

Карточки перевода рисует `src/pages/TranslationOverlay.tsx`. Их можно двигать и менять размер, положение тоже хранится в долях страницы.

**Корзина** (`src/pages/TrashPage.tsx`). Восстановление возвращает файл в библиотеку. Окончательное удаление стирает и строку в базе, и файл.

## Как запрос проходит через слои

```
React  →  invoke в libraryApi.ts  →  команда Tauri в lib.rs
                                         ├─ db.rs        SQLite
                                         ├─ import.rs    копирование PDF
                                         ├─ storage.rs   чтение, корзина, экспорт
                                         └─ worker.rs    один процесс Python
                                                └─ python-worker/worker.py
```

Интерфейс не открывает файлы и не вызывает модели сам. Все команды перечислены в `src/libraryApi.ts` и зарегистрированы в `invoke_handler` в `src-tauri/src/lib.rs`. Новая возможность обычно добавляется в оба места и в `db.rs`, если ей нужна таблица.

Python получает одну JSON-строку на stdin и отвечает одной JSON-строкой в исходный stdout. Логи библиотек идут в stderr. Команды обработки: `analyze_page`, `ocr_region`, `ocr_page`, `translate`. При старте приложения Rust один раз зовёт `warm_translator`, чтобы модель начала грузиться заранее.

Перевод страницы собирает общая очередь `src/translationQueue.ts`: она спрашивает текстовый слой, при его отсутствии — OCR, затем переводит каждый новый блок и пишет его отдельно. Очередь не зависит от монтирования читалки: можно менять страницы, книги и экраны. Панель `src/TranslationQueuePanel.tsx` показывает прогресс, отмену и повтор после ошибок. Отмена ждёт текущий вызов worker; сохранённые блоки не удаляются. Очередь живёт до закрытия приложения. Отдельного оркестратора на стороне Rust нет.

| `src/pages/PdfNavigation.tsx` | Миниатюры, оглавление и поиск по книге |
| `src/pages/PdfTextLayer.tsx` | Текстовый слой PDF.js для выделения, копирования и подсветки поиска |

| `src/pages/SelectionLayer.tsx` | Прямоугольник выделения |

| `src-tauri/src/lib.rs` | Команды Tauri, настройки, каталоги данных |
| `src-tauri/src/db.rs` | Схема через миграции и запросы |
| `src-tauri/migrations/` | Историю таблиц смотреть здесь, не выдумывать схему |
| `src-tauri/src/import.rs` | Проверка «это PDF» и копирование в библиотеку |
| `src-tauri/src/storage.rs` | Путь файла, корзина, экспорт |

Тесты Rust лежат рядом с кодом в `#[cfg(test)]`. Они поднимают временную базу и проверяют импорт, корзину, словарь, переводы и примеры.

## Данные на диске

Каталог приложения на Windows: `%APPDATA%\com.locallibrary.reader\`.

```
library/documents/    копии PDF, внутреннее имя не совпадает с исходным
library/trash/        те же копии после перемещения в корзину
data/library.db       SQLite, путь можно сменить в настройках
settings.json         тема и выбранный путь к базе
```

В базе: документы, полки, теги, закладки, заметки, блоки перевода, версии перевода, два словаря (общий и на документ). Байты PDF в базу не пишутся. Исходный файл пользователя импорт не меняет. Файл копии удаляется только при окончательном удалении из корзины. «Очистить библиотеку» убирает записи активных книг и оставляет файлы на диске.

Координаты блока и карточки — доли стороны страницы, `0.0…1.0`.

Активный перевод блока лежит и в `translation_versions` (`is_active`), и дублируется в колонке `translated_text` у блока. Повторный перевод страницы не трогает уже сохранённые области: совпавшие по месту блоки пропускаются, и если новых нет, перевод не запускается. Команды списка версий, смены активной версии и перевода одного блока заново есть в `libraryApi.ts` и в Rust. Текущая правая панель их не вызывает.

## PDF.js

Читалка, обложки библиотеки и корзина получают байты командой `read_document_pdf` и открывают их через `openPdf` в `src/pdfSetup.ts`.

Воркер PDF.js создаётся импортом `pdfjs-dist/build/pdf.worker.min.mjs?worker`. Так Vite отдаёт его и в dev-сервере, и в сборке. Адрес вида `/node_modules/.../pdf.worker.min.mjs` в WebView ломается: модуль не загружается, и на экране остаётся ошибка fake worker.

`vite.config.ts` при старте копирует в `public/` wasm PDF.js и стандартные шрифты. Они нужны, чтобы на странице рисовался текст вроде Helvetica, которого в файле нет как встроенного шрифта. Каталоги `public/pdfjs-wasm` и `public/pdfjs-standard-fonts` в Git не входят.

## Запуск в разработке

Нужны Node.js, Rust 1.85+ (edition 2024), WebView2, MSVC и Python 3.10–3.12. Точные шаги, модель и переменные `LLR_PYTHON` и `LLR_TRANSLATION_MODEL` — в [SETUP.md](SETUP.md).

```bash
npm install
npm run tauri dev
```

Vite слушает `http://localhost:1420`. Окно Tauri грузит этот адрес. Команды `invoke` в обычном браузере без окна Tauri не работают.
