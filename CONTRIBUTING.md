# Участие в разработке

Спасибо за интерес к NeuroBookShelf. Ошибки, предложения и вопросы оформляются через [Issues](https://github.com/WalkingFrozenFish/NeuroBookShelf/issues/new/choose). До большой доработки опишите задачу в Issue: это помогает согласовать поведение приложения и объём работы.

## Рабочий процесс

1. Обновите основную ветку: `git switch master` и `git pull --ff-only`.
2. Создайте короткоживущую ветку: `git switch -c feature/pdf-export`. Подходят также `fix/…`, `docs/…`, `chore/…`; изменения Codex используют `codex/…`.
3. Внесите одно связное изменение, проверьте его и отправьте ветку через `git push -u origin HEAD`.
4. Откройте PR в `master`, опишите результат и проверки. Черновик подходит для незавершённой работы.
5. Дождитесь зелёной проверки **CI**. Она включает тесты и сборку пакетов Windows и macOS. После проверки изменений сопровождающий объединяет PR через **Squash and merge**.
6. Удалите объединённую ветку и обновите локальную основную ветку. Следующую работу начинайте из неё.

В этом репозитории основная ветка называется `master`. Workflow также поддерживает `main`; переименование не требуется. Для внешних участников используется fork → ветка → PR. Код из PR не получает секреты подписи или права публикации релиза.

Подробная схема CI, требования к merge и выпуску — в [docs/WORKFLOW.md](docs/WORKFLOW.md).

## Запуск и проверки

Окружение и системные зависимости описаны в [SETUP.md](SETUP.md). Node.js — 22, Rust — stable; Python для development — 3.10–3.12. Готовые пакеты включают Python 3.11.14.

```bash
npm ci
npm test
npm run build
python scripts/check_version.py
python -m unittest discover -s tests -p 'test_*.py'
cargo test --locked --manifest-path src-tauri/Cargo.toml --lib -- --skip worker::tests
npm run tauri dev
```

Rust-тесты протокола worker требуют настроенного development Python; CI проверяет настоящий worker, OCR и перевод через отдельные smoke-скрипты с упакованным Python. Браузерные сценарии описаны в [tests/README.md](tests/README.md).

Не добавляйте модели, runtime, PDF пользователя, базы данных, токены или собранные установщики в Git. Добавляйте lock-файлы вместе с изменением зависимостей. Обновления Python-библиотек и моделей требуют обновления lock/манифеста и настоящей проверки OCR и перевода на обеих платформах; Dependabot не обновляет эту связку автоматически.

Для исправления бага полезен тест, который воспроизводит ошибку. Для изменения интерфейса опишите ручную проверку и приложите скриншот без личных данных. Сохраняйте совместимость существующей библиотеки; изменения схемы SQLite оформляются миграцией.

## Оформление изменений

Соблюдайте `.editorconfig`. Сообщение коммита должно объяснять действие: например, `Fix reader scroll containment`. Префиксы `feat:`, `fix:`, `docs:` допустимы, но не обязательны: автоматического определения версии по сообщениям коммитов нет.

Обновляйте документацию вместе с поведением приложения и добавляйте заметку в раздел Unreleased файла [CHANGELOG.md](CHANGELOG.md). Номер версии меняется отдельно в PR подготовки релиза.

## Лицензия и общение

Изменения исходников распространяются по AGPL-3.0-only, как и проект. Сторонние библиотеки и модели сохраняют собственные лицензии; не переносите чужой код без проверки условий и уведомлений.

Обсуждайте поведение и код уважительно, без перехода на личности. Сопровождающий — [@WalkingFrozenFish](https://github.com/WalkingFrozenFish); он определяет объём версии и принимает решение о merge. Срок ответа и исправления не гарантирован.
