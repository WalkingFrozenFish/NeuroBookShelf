# Cursor Development Rules

## Основное правило

Выполняй только тот этап ROADMAP.md, который явно указан пользователем.

Не переходи к следующему этапу самостоятельно.

## Перед началом работы

1. Прочитай README.md.
2. Прочитай ARCHITECTURE.md.
3. Прочитай ROADMAP.md.
4. Определи текущий этап.
5. Кратко перечисли, какие изменения собираешься сделать.

## Scope discipline

Не реализовывай функции, которые относятся к будущим этапам.

Не создавай "на будущее":

- дополнительные сервисы;
- сложные abstraction layers;
- generic framework;
- cloud infrastructure;
- auth;
- API server.

Если функциональность не нужна для текущего этапа — не добавляй её.

## Dependencies

Не добавляй dependency без необходимости.

Перед установкой новой зависимости:

1. проверь, нельзя ли решить задачу существующими средствами;
2. объясни в одном предложении, зачем нужна dependency.

Не заменяй выбранную технологию другой без прямого указания пользователя.

## Запрещено без разрешения

Не добавлять:

- NestJS
- Express
- Fastify
- PostgreSQL
- MySQL
- Redis
- Docker
- Kubernetes
- Firebase
- Supabase
- cloud services
- authentication
- telemetry
- analytics

## Code quality

Предпочитать простой читаемый код.

Не создавать abstraction ради abstraction.

Не создавать интерфейс, если существует только одна простая реализация, кроме случаев, явно обозначенных в ARCHITECTURE.md.

Не создавать файлы из нескольких строк без причины.

Не дробить код чрезмерно.

Не использовать any без необходимости.

## UI

Не придумывать крупный дизайн самостоятельно.

Сначала использовать простой функциональный интерфейс.

Приоритет:

1. usability
2. readability
3. functionality
4. visual polish

## Database

Не менять schema уже существующих таблиц без необходимости.

При изменении schema использовать migrations.

Не хранить PDF-файлы в SQLite.

## Files

Перед физическим удалением пользовательского файла всегда использовать trash flow.

Не удалять исходные PDF неожиданно.

## Error handling

Ошибки работы с:

- filesystem;
- PDF;
- SQLite;
- Python worker;
- OCR;
- translator

должны быть обработаны.

Не скрывать ошибки молча.

## Completion

После выполнения этапа:

1. перечислить созданные/изменённые файлы;
2. описать реализованное;
3. сообщить, как проверить;
4. перечислить известные ограничения;
5. остановиться.

Не начинать следующий этап.
